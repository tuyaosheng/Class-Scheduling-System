# 中小学排课系统 — 设计文档

日期：2026-08-21
状态：设计已确认，待编写实施计划

---

## 1. 目标与范围

为初中（可扩展至小学/高中）教务提供一套本地运行的排课工具：读入人工编好的任课表与规则配置，自动生成满足硬约束、尽量满足软约束的课表，并提供可视化查看与拖拽微调。

**做什么**

- 时间排布：把每个班的每门课放进「星期 × 节次」网格
- 三个年级统一求解，正确处理跨年级任课教师
- 无解时给出确定性的原因定位
- AI 事后审核课表合理性

**不做什么**

- 不做任课分配（谁带哪个班由教务人工决定，作为输入）
- 不做多校 SaaS、不做账号权限体系
- 不做走班选课（初中暂无此需求，配置结构不排斥后续扩展）

**交付形态**：本地工具 + 网页界面。PyInstaller 打包为单个 exe，教务双击运行，浏览器自动打开本地页面。

## 2. 已验证的技术前提

设计基于一次可行性验证（脚本位于 scratchpad，标记为 throwaway，不进代码库）：

| 验证项 | 结果 |
|---|---|
| 初三 32 班真实数据求解 | OPTIMAL，**0.6 秒**（512 任务 / 23,040 布尔变量） |
| 三年级 96 班（教师不跨年级） | OPTIMAL，**1.9 秒**（1,536 任务 / 69,120 变量） |
| 独立校验器复查 | 两个结果均 **0 处违规**，覆盖 9 类规则 |
| 预检层定位无解原因 | 毫秒级给出「梁艳红需要48节，可用42格，缺6格」 |
| 求解器最小冲突集 | 精确返回 5 条矛盾约束，无冗余 |

**三条由此确立的设计结论：**

1. **CP-SAT 是正确选择。** 性能有两个数量级的余量，可以放心地加软约束、加场地、加更多年级。
2. **求解速度使排课成为交互级操作。** 「改一条规则立刻重排」「拖动一节课后自动重算」在体验上可行，这直接决定了界面形态。
3. **预检层的价值高于求解器诊断。** 同一个无解场景，求解器跑 19 秒只吐 `INFEASIBLE`，预检瞬间指出具体教师和缺口数字。绝大多数「排不出来」是容量或口径问题，不该劳烦求解器。

## 3. 领域概念

### 3.1 学科系（family）

**核心建模概念。** 部分课程是主科的「影子课」，由同一位教师带同一批班，在课时分布统计上应并入主科。

经数据核对（匹配度 100%）：

| 影子课 | 归属学科系 | 匹配 | 固定窗口 |
|---|---|---|---|
| 综实1 | 物理 | 16/16 | 无 |
| 校本1 | 英语 | 17/17 | 周三 T8/T9 |
| 综实2 | 数学 | 17/17 | 周四 T8/T9 |
| 体比 | 体育 | 12/12 | 周二 T8/T9 |
| 体选 | 体育 | 12/12 | 周五 T9 |

所有「每天至少1节」「当天不超1节」类规则**按学科系统计，不按课程名统计**。

此设计解决了一处规则表面矛盾：物理周课时 4 节却要求「保证每天有1节」（5 天需 5 节）。计入综实1 后 4+1=5，约束成立。若按课程名统计则直接无解。

### 3.2 合班课（multi_class）

一位教师可在同一时刻面向多个班授课的课程。豁免「教师不分身」约束。

当前已知：体比、体选。其余课程均为 1 教师 : 1 班。

若不做此豁免，体育教师周志宁带 1/2/25 三个班的固定课直接导致无解。

### 3.3 单双周轮换（alternate）

美术与心理各 0.5 周课时，合并为「心美」1 课时，单周上美术、双周上心理。两者占用同一个时间格。

课程目录中仍分别声明美术与心理（各带 `alternate` 标记声明所属周次），课程计划中则以合并后的学科系名「心美」记 1 课时。约束编译器据 `alternate` 将两者绑定到同一格。

**教师冲突需按单双周分别判定。** 美术教师与心理教师虽占用同一时间格，但分属不同周次，不构成冲突。若简单按「一个格子一位教师」建模，会错误地丢弃其中一位教师的任课记录——验证脚本即存在此简化（教师数由 121 记为 119），正式实现必须按周次奇偶分别评估教师占用。

  periods:
    - {no: 1, section: 上午, start: "08:00", minutes: 38}
    - {no: 2, section: 上午, start: "08:45", minutes: 38}
    - {no: 3, section: 上午, start: "09:30", minutes: 38}
    - {no: 4, section: 上午, start: "10:15", minutes: 38}
    - {no: 5, section: 上午, start: "11:00", minutes: 38}
    - {no: 6, section: 下午, start: "14:20", minutes: 40}
    - {no: 7, section: 下午, start: "15:05", minutes: 40}
    - {no: 8, section: 下午, start: "15:50", minutes: 40}

  - {name: 体育,  family: 体育, venue: 操场}

  - {name: 体选,  family: 体育, venue: 操场, multi_class: true, external: true}  # 周五T9

### 4.3 课程计划（按年级）

```yaml
plans:
  初三:
    语文: 7, 数学: 5, 英语: 5, 物理: 4, 化学: 4
    道法: 3, 历史: 3, 体育: 3, 音乐: 1
    心美: 1, 综实1: 1
  初二: {}   # 待补
  初一: {}   # 待补

reserved_slots:
  初三: [[0,9],[1,8],[1,9],[2,8],[2,9],[3,8],[3,9],[4,9]]
  # 班会(周一T9)、体比(周二T8/9)、校本1(周三T8/9)、综实2(周四T8/9)、体选(周五T9)
```

初三系统求解合计 37 节，占满可用的 37 格。另 8 格由教务已固定安排，系统不排课不校验，见下方说明。

**实现口径变更（2026-08-22）**：校本1/综实2/体比/体选/班会最初按 `pin_window`（锁定窗口）建模——周课时数小于等于窗口长度即可，任务在窗口内自由选格。这在周课时数据不准（比 6.1 节的固定窗口短）时看似能求解，实则是假象：窗口内的自由度掩盖了教师另一个班的课被挤到窗口外、与该课实际发生时间对不上的问题。数据订正为「周课时=窗口长度」（物理真实值）后，矛盾暴露——校本1、综实2 的每一位任课教师都同时带 2 个班，窗口=课时=2 迫使两个班的任务被摁死在完全相同的两格，构成教师分身，直接 INFEASIBLE。

这几门课的具体时间和任课本就由教务直接决定、不需要系统求解，因此改为「教务固定占位」：`courses.yaml` 标记这些课程 `external: true`（不生成任务、不生成 pin_window），对应的时段整体列入 `plans.yaml` 的 `reserved_slots`，导入器据此生成一条年级级、不限课程/教师的 `forbid_slots` 规则，把这些格位从求解域里整体排除。导出 Excel 时这些格位标占位文字，不留白也不由系统填内容；真实的任课分配等教务另外提供的任课表数据接入。

### 4.4 任课表

从现有 Excel 导入（`任课与排课说明.xlsx` 格式），不需重新录入。列映射：姓名 / 任教年级 / 学科 / 任教班 / 周课时 / 职务 / 固定节次 / 不能排课节次 / 排课要求 / 备注。

后四列的中文规则文本由解析器转为结构化规则（见 5.3）。

### 4.5 场地

容量留空表示不限制。界面可编辑。

```yaml
venues:
  - {name: 物理实验室, capacity: 3}
  - {name: 化学实验室, capacity: 3}
  - {name: 生物实验室, capacity: 3}
  - {name: 操场,      capacity: null}   # 待确认实际容量
  # 音乐在普通教室上课，不声明场地
```

**容量压力提示**：物理实验室 3 间，单年级 32 节综实1 占 45×3=135 容量的 24%；三年级 96 节时占用率 71%，叠加时段禁排后会明显吃紧。M2 阶段即纳入模型。

## 5. 规则 DSL

规则是数据不是代码。每条规则由**类型 + 作用域 + 参数 + 模式**构成。

### 5.1 结构

```yaml
- type: daily_min
  scope: {grade: 初三, family: [语文, 数学, 英语, 物理]}
  params: {n: 1}
  mode: hard

- type: avoid_after
  scope: {grade: "*"}
  params: {after: 体育, avoid: [语文, 数学, 英语]}
  mode: soft
  enabled: true
  weight: 8
```

**作用域五维**：`grade` / `family` / `course` / `teacher` / `class`。任意组合，未指定即通配。

这使得同一类规则可以在不同年级取不同参数，互不干扰：

```yaml
- {type: weekday_exact, scope: {grade: 初三, course: 体育}, params: {weekdays: [周一,周三,周四], n: 1}, mode: hard}
- {type: weekday_exact, scope: {grade: 初二, course: 体育}, params: {weekdays: [周二,周五],      n: 1}, mode: hard}
```

**软约束**额外带 `enabled`（开关）与 `weight`（权重），界面上分别呈现为开关和滑块。

### 5.2 规则类型清单

| 类型 | 含义 | 参数 | 默认模式 |
|---|---|---|---|
| `forbid_slots` | 禁排时段 | `slots` | hard |
| `pin_window` | 锁定在窗口内 | `slots` | hard |
| `daily_min` | 每日至少 N 节 | `n` | hard |
| `daily_max` | 每日至多 N 节 | `n` | hard |
| `weekday_exact` | 指定星期各 N 节 | `weekdays`, `n` | hard |
| `consecutive` | 连堂 | `days`, `length` | hard |
| `spacing` | 同教师两班间隔 | `min_gap` | soft |
| `alternate_weeks` | 单双周轮换 | `pair` | hard |
| `venue_capacity` | 场地并发上限 | `venue`, `capacity` | hard |
| `preferred_periods` | 时段偏好 | `prefer`, `spread` | soft |
| `avoid_after` | 课序对约束 | `after`, `avoid` | soft |
| `teacher_balance` | 教师日负荷均衡 | `max_dev` | soft |

清单覆盖现有 Excel 中出现的全部规则写法，以及行业通行的软性偏好。

### 5.3 中文规则解析

Excel 中的规则文本形态规整（实测 22 种写法），用正则按「周X」切段解析：

- `周二上午不排课` → 周二 1-5 节
- `周一4、5节，周三上午不排课` → 周一 4,5 节 + 周三 1-5 节
- `周二下午2、3、4节` → 周二 7,8,9 节（下午第 N 节 = 第 5+N 节）
- `周五第4，5节` → 周五 4,5 节（注意此处逗号是数字分隔，不是子句分隔）

解析器输出结构化规则，**并把解析结果回显给用户确认**，避免歧义静默通过。

## 6. 分层架构

```
配置层（YAML + Excel）
  ↓
领域模型（pydantic）
  ↓
预检层 L1 ──────────── 毫秒级，拦截绝大多数无解
  ↓
约束编译器（Rule → CP-SAT）
  ↓
求解层（两阶段 CP-SAT）── SolutionCallback ──WebSocket──> 前端
  ↓                    ↘ 无解
校验层（独立实现）        诊断层 L2（最小冲突集）
  ↓                    ↙
AI 层 L3（审核 / 翻译 / 建议）
  ↓
界面层（Vue 3）
```

**贯穿原则：AI 不参与任何算术与硬性判定。** 「对不对」由确定性代码回答，AI 只负责「合不合理」与「说人话」。

## 7. 求解策略

### 7.1 两阶段

- **Phase 1 求可行**：仅硬约束，目标是找到任意可行解。实测 96 班 1.9 秒。
- **Phase 2 求满意**：以 Phase 1 结果作 `AddHint` 热启动，加入软约束加权目标函数，限时 30–60 秒优化。每获得更优解经 `SolutionCallback` 推送一帧至前端。

保证**永远先有一张能用的表**，优化过程可随时叫停。

### 7.2 局部重排

支撑拖拽微调：用户拖动一节课后，将不受影响的课全部固定为常量，只重解受影响的子问题（该班 + 该教师 + 该场地相关），毫秒级返回。

### 7.3 变量模型

对每个「(班级, 课程)」教学任务 `i` 与每个时间格 `s`，建立布尔变量 `x[i][s]`。

规模：三年级约 1,536 个任务 × 45 格 = 69,120 变量，CP-SAT 舒适区。

## 8. 诊断层

| 层 | 触发时机 | 输出示例 | 实测性能 |
|---|---|---|---|
| **L1 预检** | 求解前，总是运行 | `[教师超载] 梁艳红需要48节，可用42格，缺6格` | 毫秒级 |
| **L2 冲突集** | 预检通过但无解 | `4班物理「周一至少1节」…共5条` | 秒级 |
| **L3 AI** | L1/L2 有输出时 | 人话解释 + 松绑方案排序 | 一次 API 调用 |

### L1 检查项

1. **教师超载**：任课总节数 > (总格数 − 禁排格数)
2. **班级超载**：周课时总和 > 每周总格数
3. **规则自相矛盾**：如「每天至少1节」但该学科系周课时 < 上课天数
4. **固定窗口容量不足**：窗口格数 < 需排节数
5. **场地容量不足**：某课程总需求 > 容量 × 可用格数

### L2 实现

对可放松的规则（`daily_min` / `daily_max` 等）挂 assumption 布尔开关，`OnlyEnforceIf` 绑定；无解时调用 `SufficientAssumptionsForInfeasibility()` 取回最小矛盾子集，再映射回人类可读描述。

硬性物理约束（教师不分身、班级不重课）不挂 assumption——它们不可放松，出现在冲突集里没有意义。

## 9. AI 审核

### 输入

- 课表的紧凑文本表示
- 生效的规则配置
- 独立校验器的确定性结论
- 统计指标：各班各科时段分布、教师日负荷方差、连堂分布等

### 输出

结构化 findings：

```json
{
  "severity": "warning",
  "scope": {"class": 7, "day": "周一"},
  "issue": "7班周一有2节数学（第5、7节），规则只约束了下限未约束上限",
  "suggestion": "为数学系增加 daily_max: 1 规则"
}
```

### 职责边界

**该 AI 干**：发现规则未覆盖的隐性不合理；指出规则配置本身的疏漏；把冲突集翻译成教务语言并给出松绑方案排序。

**不该 AI 干**：判断是否撞课、核对课时数、计算容量是否足够。这些由校验器给出确定结论后，**作为既定事实喂给 AI**。

### 真实案例

验证阶段求解器排出的表中，7 班周一有 2 节数学。规则只写了「保证每天有1节」（下限）未写上限，因此完全合法——但教务一眼即知不合理。这正是 AI 审核的目标场景。

## 10. 界面

### 视图

1. **班级课表**（主视图）— CSS Grid 绘制 5×9 网格，SortableJS 拖拽
2. **教师课表** — 按教师查看工作量与分布
3. **场地占用** — 实验室、操场的并发情况
4. **求解监控** — 目标值下降曲线（ECharts）+ 求解器日志 + 中间解逐帧刷新
5. **诊断面板** — 预检问题、冲突集、AI 审核报告
6. **配置编辑** — 规则列表，软约束带开关与权重滑块

### 关于「看到程序怎么算」

必须明确的技术事实：**CP-SAT 是黑盒求解器，内部为布尔子句学习，不是「一节一节往格子里放」**，且 0.6 秒即结束。逐格放置的过程在真实求解中不存在。

因此拆为三类：

- **真实可展示**：中间解流（课表逐版变好）、目标值曲线、求解器日志、约束满足热力图
- **可做但非真实**：由最终解反推放置顺序做回放动画。界面须标明「回放演示」，不得暗示为实时求解过程
- **最高价值**：拖拽微调时的实时反馈——拖起一节课即高亮所有合法落点（绿）与冲突落点（红，附违反的规则名），松手后局部重排

### 拖拽交互

落点合法性由前端本地计算，不走后端，无延迟。落子后调用后端局部重排。

**`compiler.py` 与 `verifier.py` 必须独立实现，不得共享约束逻辑。** 若校验器复用编译器代码，同一个 bug 会同时骗过两侧，「0 处违规」将失去意义。验证阶段即遵循此原则。

## 13. 实施路线

| 阶段 | 内容 | 完成标志 |
|---|---|---|
| M1 | 领域模型、配置体系、Excel 导入、中文规则解析 | 现有 Excel 可转为结构化数据并回显确认 |
| M2 | 规则 DSL、约束编译器、硬约束求解、场地约束 | 命令行排出初三课表 |
| M3 | 独立校验器、L1 预检、L2 冲突集 | 排不出来时能指出具体原因 |
| M4 | 软约束、两阶段优化、权重调节 | 课表从「能用」到「好用」 |
| M5 | Web 界面、拖拽微调、求解监控 | 教务可独立操作 |
| M6 | AI 审核 | 出表后自动体检并给出报告 |
| M7 | 三年级合排、打包 exe | 可交付 |

M1–M3 可仅凭现有初三数据完成，不依赖待补信息，构成第一份实施计划的范围。M4 及之后各阶段在前序完成后另行编写计划——七个阶段合为一份计划过大，不利于执行与复查。
