## 1. 背景

上一份设计文档（课程配置扩展与跨年级防冲突）梳理"从头到尾操作流程"时发现一个断点：年级日历（`calendars.yaml`）设计完了数据结构，但 `compiler.py`/`verifier.py`/`precheck.py`/`importer.py`/`exporter.py`/`ruletext.py` 现在全部读 `calendar.py` 里写死的全局常量（5 天、9 节），不是按年级读取。这份文档就是把这个断点补上。

同时拿到了真实的作息时间表（`作息表模板.xlsx` 的七/八年级 + `初三任课安排.xls` 里嵌的图片，对应九年级），确认了几件事：

- 七年级 8 节、八年级 9 节、九年级 9 节——节数确实按年级不同
- 三个年级上下课时间确实错峰，不是同一套时钟
- 九年级周一时间因升旗仪式整体后移，与周二到周五不同——**按你的决定，不单独建模周一，统一用周二到周五这一套**
- 九年级第一节和第二节之间有 35 分钟"跑操"，比普通课间休息长——**按你的决定，不用管，只处理午休这一种"不算相邻"的边界**

## 2. 现状：`calendar.py` 都被谁用了

```python
# scheduler/core/calendar.py（现状）
DAYS = ['周一', '周二', '周三', '周四', '周五']
PERIODS_PER_DAY = 9
N_SLOTS = 45
MORNING = (1,2,3,4,5)
AFTERNOON = (6,7,8,9)

def day_index(name): ...
def slot_index(day, period): ...
def slot_of(index): ...
def section_period(section, n): ...   # "上午/下午第N节" → 绝对节次
```

逐文件核实过的消费者：

| 文件 | 用到什么 |
|---|---|
| `compiler.py` | `N_SLOTS`（变量枚举范围）、`DAYS`（按天分组）、`PERIODS_PER_DAY`（半天窗口、连堂枚举）、`slot_index`/`slot_of` |
| `verifier.py` | 同上，独立复用一份 |
| `precheck.py` | `N_SLOTS`（容量校验分母） |
| `importer.py` | `slot_index`（解析"周X第Y节"文本）、`PERIODS_PER_DAY`（校验节次是否越界） |
| `exporter.py` | `DAYS`/`PERIODS_PER_DAY`（简单网格版表头 + 教务模板版的固定列偏移公式） |
| `ruletext.py` | `day_index`/`section_period`/`MORNING`/`AFTERNOON`/`PERIODS_PER_DAY`（解析"周二下午2节"这类中文） |
| `cli.py` | `N_SLOTS`（状态信息打印） |

`MORNING`/`AFTERNOON` 精确对应"第 5/6 节之间的午休边界"——`section_period` 拿它俩把"上午/下午第 N 节"换算成绝对节次，`compiler.py` 的 `adjacent_pairs()` 拿一个等价的 `NO_ADJACENT = {(5,6)}` 常量排除跨午休的连堂判定。这两处现在是两份独立写死的边界，语义是同一件事。

## 3. 新数据模型

### 3.1 `GradeCalendar`

```python
class GradeCalendar(BaseModel):
    days: List[str]                                  # 如 [周一, 周二, 周三, 周四, 周五]
    periods_per_day: int
    midday_break_after: int                           # 第几节后午休，如 5 表示 5/6 节之间
    clock_times: Optional[List[Tuple[str, str]]] = None  # 每节的 (开始, 结束)，与 periods_per_day 等长；未配置时为 None
    reserved_slots: List[dict] = []                    # [{day, period, label}]，教务固定占位

    @property
    def n_slots(self) -> int:
        return len(self.days) * self.periods_per_day

    @property
    def morning(self) -> range:
        return range(1, self.midday_break_after + 1)

    @property
    def afternoon(self) -> range:
        return range(self.midday_break_after + 1, self.periods_per_day + 1)

    def day_index(self, name: str) -> int: ...
    def slot_index(self, day: int, period: int) -> int: ...
    def slot_of(self, index: int) -> Tuple[int, int]: ...
    def section_period(self, section: Optional[str], n: int) -> int: ...
    def adjacent_pairs(self) -> List[Tuple[int, int]]:
        """连堂可用的相邻节次对，排除午休边界。"""
        return [(p, p + 1) for p in range(1, self.periods_per_day)
                if p != self.midday_break_after]
```

这些方法是把现在 `calendar.py` 模块里的自由函数原样搬进来，行为不变，只是从"读全局常量"变成"读 `self` 上的字段"——`slot_index`/`slot_of` 的算法本身完全没变（`day * periods_per_day + period - 1`），只是 `periods_per_day` 从全局常量变成实例字段。

**为什么只存一个 `midday_break_after` 整数，不是一般化的"不相邻节次对列表"**：现在唯一在用的边界就是午休，`MORNING`/`AFTERNOON` 现状也只切一刀。跑操那类更细的间隙按你的决定不用管，没有第二个真实需求支撑"一般化列表"这个复杂度，做成单个整数就够，将来真有第二种间隙再扩展成列表不迟。

七/八年级的 `clock_times`/`periods_per_day`/`midday_break_after` 是直接从这次拿到的两份作息表填的（七年级第 4/5 节间午休、八年级第 5/6 节间），可以作为真实打样数据。九年级沿用现在 `plans.yaml` 里已有的 `reserved_slots`，`clock_times` 用刚提取出来的周二到周五时间表。

`grade_calendars` 的 key 集合就是系统当前支持的年级列表，不用单独建一份"年级注册表"——新增年级＝加一个 key（自然通过"空课表模板上传"产生），删除年级＝删一个 key（要检查 `plans.yaml` 有没有还在引用，悬空引用拦下，和课程设置那套校验模式一致）。

## 4. 关键设计决定

### 4.1 挂载在 `Dataset` 上，不是到处加参数

`Dataset` 新增 `calendar: GradeCalendar` 字段，在 `importer.py` 构造 `Dataset` 时用 `cfg.calendar_of(grade)` 填入。

这样选是因为：`compiler.py`/`verifier.py`/`precheck.py` 里绝大多数函数**已经**拿得到 `dataset`（直接传入，或者通过 `CompiledModel.dataset`），不需要重新设计一套参数传递路径，只是把 `cal.N_SLOTS` 换成 `c.dataset.calendar.n_slots`（或 `dataset.calendar.n_slots`）这种访问方式。真正需要加参数的只有两类：

- `ruletext.py` 的解析函数：现在完全没有 grade/calendar 上下文，纯文本进纯 dict 出，需要新增一个 `calendar: GradeCalendar` 参数
- `exporter.py`/`cli.py` 里几个独立的工具函数：原本直接 `import calendar as cal` 用模块常量，需要显式传入

### 4.2 `slot_index`/`slot_of` 从模块函数变成 `GradeCalendar` 方法

这不是选择，是必须——一旦 `periods_per_day` 按年级不同，`slot_index(day, period) = day * periods_per_day + period - 1` 这个换算公式本身就依赖是哪个年级，不可能再是一个不带年级信息的全局函数。`day_index`/`section_period` 同理（`section_period` 依赖 `midday_break_after`）。

### 4.3 明确排除的

- **不做"跑操"这类次要间隙的建模**：`midday_break_after` 只处理午休这一个边界，其余节次之间一律算相邻。
- **不做周一的独立时间表**：`clock_times` 只存一份（对应周二到周五），周一实际时间更晚这件事不进数据模型，是有意简化，不是遗漏。
- **不自动从时钟间隙推导午休边界**：`midday_break_after` 是配置时显式声明的整数，不是运行时从 `clock_times` 里找最大间隙算出来的。省掉一层"猜测"逻辑，配置错了也容易肉眼发现（一个整数，不是隐藏在算法里的推导结果）。

## 6. 已知的连带问题

### 6.1 教务模板版导出（`export_to_template`）不能再共用一份模板文件

现在的实现假设一份 `课程表模板.xlsx`（固定行列布局）能导出所有年级。一旦 `periods_per_day` 按年级不同，列偏移公式 `_TEMPLATE_FIRST_DAY_COL + day * periods_per_day + (period - 1)` 算出来的列位置对不同年级是不同的，而**真实的教务模板文件本身的列数也必须跟着变**（七年级模板每天只有 8 列，不是 9 列）。也就是说，模板导出这条路以后大概率需要**按年级各自一份模板文件**，不是一份模板打天下。这次不展开解决，标记为实施阶段需要单独处理的连带问题。

### 6.2 现有测试大面积依赖全局 `cal.DAYS`/`cal.N_SLOTS`

搜过一遍，测试文件里直接 `from scheduler.core import calendar as cal` 然后用 `cal.N_SLOTS`/`cal.slot_index` 构造测试数据的地方非常多（`test_compiler_base.py`、`test_verifier.py`、`test_precheck.py`、`test_solve_e2e.py` 等）。这些测试需要跟着改成"先构造一个 `GradeCalendar` 测试夹具，再从这个夹具取值"，是这次改动里工作量最大的一块，比生产代码本身的改动量更大。建议实施阶段先把这类测试用的 `GradeCalendar` 夹具（比如复用九年级现在这套 5×9 的真实数据）定下来，再批量迁移断言，不要逐个文件各写各的夹具。

## 7. 实施建议

这次改动是贯穿求解主链路的核心重构，风险和现有测试的迁移成本都不小，建议：

1. 先加 `GradeCalendar`/`calendars.yaml`/`SchedulerConfig.calendar_of`，`Dataset` 加字段，但**先只给九年级建一份数据**（就是现在的 5×9 常量原样照抄成九年级的 `GradeCalendar`），不改任何消费方代码——这一步纯新增，不动现有行为，可以先验证数据结构本身没问题。
2. 再逐文件把 `cal.xxx` 替换成 `dataset.calendar.xxx`，每改一个文件跑一次对应测试，出错就地修，不要一次性全改完再统一调试。
3. 全部替换完、九年级测试全绿之后，再加七年级/八年级的 `calendars.yaml` 数据，验证跑一个不同 `periods_per_day` 的年级确实能正确求解——这一步才是真正验证"参数化"这件事本身是对的，前面步骤只是"没把九年级做坏"。
4. `export_to_template` 的连带问题（6.1）放到最后，且可能需要你另外提供七/八年级各自的教务模板文件。
